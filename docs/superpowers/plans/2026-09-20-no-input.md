# No-Input Handling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A caller who says nothing after a prompt hears "I didn't hear anything." and the question again, then the keypad offer, then an agent; the server drives it with one timer per call.

**Architecture:** A synthetic `silence` inbound frame that the server produces after `NO_INPUT_MS` plus an estimate of the prompt's playback; the core resolves it without a model call by walking the existing ladders with a `no_input` ack in front; a playback estimate helper next to the clip index; a per-call timer in the adapter with a generation counter so a late-arriving answer wins the race; scenario and REPL support.

**Tech Stack:** TypeScript strict ESM, pnpm, vitest (fake timers). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-20-no-input-design.md`. Read it first. The plan wins on small conflicts; each is marked "Deviation:".

**Conventions for every task:**

- Tests colocated as `*.test.ts`; run one with `pnpm vitest run <path>`, all with `pnpm test`; typecheck with `pnpm typecheck`.
- Extensionless imports; strict TS; `noUncheckedIndexedAccess` is on.
- Commit after every task with the message shown, one task per commit, exactly one writer at a time; every commit message ends with a blank line then `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Never set, read, or print `TYPESAFE_API_KEY` or `FISH_AUDIO_API_KEY`; never run `--client jev`, `--client record`, or `prompts:generate` without `--dry-run`. Only Jason runs those (Task 7).
- `pnpm test` stays green after every task. `pnpm regress` says no changes until Task 5 adds scenarios (then `--update`, stub only). The cassette is never touched: a silence turn makes no model call and no question changes.

- [ ] **Step 2: Implement `src/prompts/playback.ts`.**
```ts
import { readdirSync, readFileSync } from 'node:fs';
import { join } from 'node:path';
import type { OutboundFrame } from '../channel/frames';

const WORDS_PER_SECOND = 2.5;
const MIN_TEXT_MS = 500;
/** A clip we could not measure (mp3, missing) is assumed to be this long. */
const UNKNOWN_CLIP_MS = 1500;

/** Duration of a PCM WAV from its header, or null when the buffer is not a parseable WAV. */
export function wavDurationMs(b: Buffer): number | null {
  if (b.length < 44 || b.toString('ascii', 0, 4) !== 'RIFF' || b.toString('ascii', 8, 12) !== 'WAVE') return null;
  let pos = 12; let byteRate = 0; let dataSize: number | null = null;
  while (pos + 8 <= b.length) {
    const id = b.toString('ascii', pos, pos + 4); const size = b.readUInt32LE(pos + 4);
    if (id === 'fmt ' && pos + 8 + 16 <= b.length) byteRate = b.readUInt32LE(pos + 16);
    if (id === 'data') { dataSize = Math.min(size, b.length - pos - 8); break; }
    pos += 8 + size + (size & 1);
  }
  if (!byteRate || dataSize === null) return null;
  return Math.round((dataSize / byteRate) * 1000);
}

export function textEstimateMs(text: string): number {
  const words = text.trim().split(/\s+/).filter(Boolean).length;
  return Math.max(MIN_TEXT_MS, Math.round((words / WORDS_PER_SECOND) * 1000));
}

/** filename → ms for every wav directly under dir; mp3s are skipped (estimated at playback). */
export function clipDurations(dir: string): Map<string, number> {
  const out = new Map<string, number>();
  let names: string[];
  try { names = readdirSync(dir); } catch { return out; }
  for (const name of names) {
    if (!/\.wav$/i.test(name)) continue;
    const ms = wavDurationMs(readFileSync(join(dir, name)));
    if (ms !== null) out.set(name, ms);
  }
  return out;
}

/** How long the frames take to play, for the no-input timer; approximate by design. */
export function playbackEstimateMs(frames: readonly OutboundFrame[], durations: ReadonlyMap<string, number>): number {
  let total = 0;
  for (const f of frames) {
    if (f.type === 'text') total += textEstimateMs(f.token);
    else if (f.type === 'play') total += (durations.get(f.source.slice(f.source.lastIndexOf('/') + 1)) ?? UNKNOWN_CLIP_MS) * Math.max(1, f.loop);
  }
  return total;
}
```
Deviation from spec §4: mp3 clips use the fixed unknown-clip estimate rather than the recording text's word count (the adapter does not have the recording text at send time).

`adapter.ts`:
```ts
export interface AdapterDeps {
  ...
  /** Silence after a prompt's estimated playback before a silence turn runs; 0 disables. */
  noInputMs?: number;
  /** wav filename → ms, from clipDurations(audioDir); used for the playback estimate. */
  clipDurations?: ReadonlyMap<string, number>;
}

interface NoInput { timer: ReturnType<typeof setTimeout>; generation: number }
const noInputTimers = new Map<string, NoInput>();
const noInputGeneration = new Map<string, number>();

function clearNoInput(callSid: string): void {
  const t = noInputTimers.get(callSid);
  if (t) { clearTimeout(t.timer); noInputTimers.delete(callSid); }
  noInputGeneration.set(callSid, (noInputGeneration.get(callSid) ?? 0) + 1);
}

/** Arm the no-input timer after a prompt: NO_INPUT_MS after the frames have (approximately) played. */
function armNoInput(deps: AdapterDeps, entry: CallEntry, frames: readonly OutboundFrame[]): void {
  const wait = deps.noInputMs ?? 0;
  if (wait <= 0) return;
  clearNoInput(entry.callSid);
  const generation = noInputGeneration.get(entry.callSid) ?? 0;
  const delay = wait + playbackEstimateMs(frames, deps.clipDurations ?? new Map());
  const timer = setTimeout(() => {
    noInputTimers.delete(entry.callSid);
    void deps.store.enqueue(entry.callSid, async (e) => {
      // A real turn since the arm bumped the generation; the caller answered at the last second.
      if (e.ended || (noInputGeneration.get(e.callSid) ?? 0) !== generation) return;
      e.frames.write('in', silenceFrame());
      await turn(deps, e, silenceFrame());
    }).catch((err) => deps.log(`${entry.callSid}: silence turn failed: ${describe(err).message}`));
  }, delay);
  timer.unref?.();
  noInputTimers.set(entry.callSid, { timer, generation });
  entry.frames.write('log', { noInputArmedMs: delay });
}
```
In `turn()`: after `sendFrames` for a `prompt` decision, `armNoInput(deps, entry, run.result.frames)`; for `complete`/`handoff`, `clearNoInput(entry.callSid)`. In `handleSocketMessage`: `clearNoInput(ctx.callSid)` as soon as a `prompt` (final or partial), `dtmf`, or `interrupt` frame arrives for a known live call (before the partial/terminator early returns), and on a reconnect `setup`. In `handleSocketClose`: clear it, and delete both map entries when the call is gone. `deps.store.end` path: clear.

## Deviations recorded during execution

### Task 1 (`ad4e47a`)

- Absorbed Task 2 (the `no_input` prompt, its tag, and the clip snapshot row) rather than leaving it for a separate commit: `resolve()` already builds a decision's outbound frames eagerly, the way it does for every other event, so a silence decision's `no_input` ack has to resolve to real prompt text the moment any Task 1 test drives a silence turn through `resolve()` — otherwise `decisionToFrames`/`spokenText` throw "unknown prompt id: no_input". The manifest and tag content were already fully specified by the spec and the plan's own Task 2 step, so `no_input` was added to `src/prompts/manifest.json`, tagged `[calm]` in `src/prompts/tags.json`, and folded into `src/prompts/__snapshots__/clips.test.ts.snap` here. No audio was generated or recorded.
- `src/harness-text/metrics.ts` needed no code change: its turn-counting branches on `event.type === 'prompt'` versus everything else, so a `silence` event falls into the same "not a caller utterance, just re-baselines the slot count" branch as `dtmf` and `setup` turns already did.
- Cosmetic: `handleSilence`'s `s.promptedFor === 'confirm' ? 'intent' : s.promptedFor` ternary is redundant — `failAttempt` already guards `target === 'confirm'` and maps it to `'intent'` itself. Left in place as documented-defensive rather than removed.
- Forward note, carried into the Task 7 amendment above: two of Task 5's scenarios (`silence-then-answer`, `silence-confirm-dtmf-then-1`) answer past a silence step, which puts a `silence` entry in `history` ahead of later model turns. The spec's §6 claim that "the cassette is untouched" holds only for a silence that ends the ladder in a re-ask, the keypad menu, or a handoff — not for one a scenario continues past.

### Task 3 (`3a65664`, fixed by `60d5f0a`)

- The plan's own worked example for `textEstimateMs` was wrong: it expected the greeting's 11 words to estimate 4000 ms, but 11 words at 2.5 words/second is 4400 ms. `60d5f0a` fixed the test's expectation and switched the implementation to count words plainly (split on whitespace) rather than the fancier counting the first pass used.
- `playbackEstimateMs` uses the fixed `UNKNOWN_CLIP_MS` estimate for an mp3 clip (no WAV header to parse), not the recording text's word count as spec §4 suggests, because the adapter only has the clip's file name at send time, not its recording text.

### Task 4 (`134cf47`)

- The generation counter lives in adapter-module maps (`noInputTimers`, `noInputGeneration`), the same way `endGraceTimers` already does, rather than on `CallEntry`: `clearNoInput` bumps the generation and `armNoInput` reads it back, and `forgetNoInput` (dropping both map entries outright) runs only once a call is gone from the store, so the generation survives a reconnect.
- The inbound-activity clear (`prompt`, `dtmf`, or `interrupt` clears the timer) sits before the partial-prompt drop and the `#`/`*` early returns in `handleSocketMessage`, not after: a partial prompt or a bare terminator digit is still a caller who is not silent.
- `turn()`'s `if (ending) clearNoInput(entry.callSid)` is unreachable in practice today: by the time a turn's decision is `complete`/`handoff`, either a real inbound frame already cleared the timer above, or (for a silence-driven turn) the fired timer's own callback already removed its map entry before enqueuing the turn. Kept as insurance rather than removed.
- The "is a no-op when the caller spoke just as it fired" test advances fake timers synchronously (`vi.advanceTimersByTime`, not the async form) on purpose, so the timer's callback queues the silence turn before anything drains the per-call queue, and the real inbound message that follows finds the generation already moved on.
- After a handoff, `vi.getTimerCount()` is 1, not 0: the end-close backstop timer is still armed until the socket actually closes.
- The end-to-end no-input test in `src/server/server.test.ts` takes about 4.5 seconds in real time (the greeting is spoken TTS text, so the wait is the configured 50 ms plus the ~4400 ms estimate for the greeting's 11 words), so it carries its own longer `it(...)` timeout.
- The startup log line uses the effective `noInputMs` (after test overrides), not the raw config value.
- `src/harness-text/replay.ts` could not replay a recorded `silence` frame-log line, because `parseInbound` never accepts `{ type: 'silence' }` by design (it is server-generated, never sent over the wire). Fixed in Task 5 by special-casing the exact recorded shape inside `replay.ts` itself, leaving `parseInbound` untouched.

### Task 4, second pass (review of `134cf47`)

The first pass cleared the wait on caller activity but only re-armed after a `prompt` decision, so any inbound frame that cancelled the wait without producing a prompt left the caller on an open line for good: a member-ID digit that only fills the keypad buffer, a barge-in, a relay `error` frame, a `#`/`*` terminator, a non-final prompt, and the apology a thrown turn speaks. The re-arm rule is now "unless the call is ending, restart the wait after a prompt decision **or** whenever `session.promptedFor` is still set", plus an explicit `armNoInput(deps, entry, [])` on the two paths in `handleSocketMessage` that return before any turn runs. A re-arm with no frames of its own waits the bare `NO_INPUT_MS`. This is broader than the review asked for (it named `ignore`): `replay` and the unreachable-from-the-adapter `hold` fall under the same rule, since both leave the caller owing an answer to something.

- The estimate is measured on what `sendFrames` actually put on the wire: `sendFrames` now returns those frames, already rewritten by `spokenDigits`. A summary's member ID is read out as eight separate digits, which takes about 2.4 seconds longer than the readable "4471 8293" the session keeps, so estimating on the pre-rewrite frames cut the wait short by that much. Frames that were dropped (no socket, or a failed send) are excluded: Twilio spends no time playing a frame it never received.
- `forgetNoInput` is exported and called from the idle sweep in `index.ts` as well as from the socket close of a call the store no longer has. The generation counter deliberately survives an ordinary close, so a reconnect cannot hand an already-queued closure a generation it would match a second time; only a call that is genuinely gone drops it.
- **TwiML change:** `partialPrompts` goes from `"false"` to `"true"` in `src/server/twiml.ts`. This is for the no-input wait alone — the adapter still runs a turn only on a final prompt — but it does change what Twilio sends on every call and it is the one thing in this task that is visible outside the server. A partial now cancels the wait at the caller's first syllable instead of after the whole utterance is transcribed, and it restarts a bare `NO_INPUT_MS` wait so a slow speaker is not interrupted. The cost is frame-log volume: every partial writes a `droppedPartial` line and a `noInputArmedMs` line.
- `wavDurationMs` keeps walking the RIFF chunk list until it has both `fmt ` and `data` rather than stopping at `data`. RIFF does not fix the chunk order, and a samples-first file previously measured as unparseable and fell back to the fixed unknown-clip estimate.
- The end-to-end no-input case in `src/server/server.test.ts` now writes a real 200 ms WAV as `greeting.0.wav`, so the greeting is one recorded clip and the test exercises `clipDurations` end to end. It runs in about 260 ms instead of the 4.5 seconds the spoken-text variant needed, and no longer carries its own `it(...)` timeout.
